## 1. 科学的研究・理論

### 1.1 Exploration vs Exploitation（探索と活用のジレンマ）

**多腕バンディット問題**は、思考vs試行の最も数学的に洗練されたモデルである。

カジノに複数のスロットマシン（腕）があるとき、既に良い結果が出ているマシンを使い続けるか（**Exploitation＝活用**）、まだ試していないマシンを試すか（**Exploration＝探索**）——この判断が累積報酬を最大化する鍵になる。

**主要アルゴリズムと示唆：**

| 戦略 | 仕組み | 思考/試行への示唆 |
|------|--------|-------------------|
| **Epsilon-Greedy** | 確率εでランダム探索、1-εで最善を活用 | 大半は「うまくいっていること」を続けつつ、一定割合で新しいことを試す |
| **UCB（Upper Confidence Bound）** | 不確実性が高い選択肢に楽観的なボーナスを付与 | **知らないことほど試す価値がある**（情報価値の概念） |
| **Thompson Sampling** | ベイズ推定で各選択肢の期待値の分布を更新 | 試行結果から信念を更新し続ける。最もデータ効率が良い |

**核心的洞察：** 最適戦略は「序盤は探索を多く、終盤は活用に集中する」（ε-decreasing）。人生やプロジェクトに置き換えると：

- **序盤（若い時期、プロジェクト初期）：** 試行比率を高く（70-80%）
- **終盤（確立期、デッドライン前）：** 思考・活用比率を高く（70-80%）

> 📚 出典: Auer, P., Cesa-Bianchi, N., & Fischer, P. (2002). "Finite-time Analysis of the Multiarmed Bandit Problem." *Machine Learning*, 47(2-3), 235-256. / Lai, T.L. & Robbins, H. (1985). "Asymptotically efficient adaptive allocation rules." *Advances in Applied Mathematics*, 6(1), 4-22.

### 1.2 Design Thinking のプロトタイピング理論

IDEO/スタンフォードd.schoolのDesign Thinkingは5段階プロセスを提唱：

```
共感 → 問題定義 → アイデア創出 → プロトタイプ → テスト
 [思考]   [思考]      [試行的思考]     [試行]      [試行→思考]
```

重要な原則：**「考えるためにつくる（Build to Think）」**

プロトタイプは「答え」ではなく「問い」を具体化するツール。つまり**試行は思考の一形態**であり、両者は対立しない。

**「早く安く失敗する」設計原則：**
- プロトタイプの忠実度を意図的に低く保つ（ローファイ・プロトタイプ）
- 完璧を求めず、学習目的を明確にしてから作る
- 1つの仮説につき1つのプロトタイプ

### 1.3 Lean Startup: Build-Measure-Learn ループ

Eric Riesの**Build-Measure-Learn**ループは、サイクル速度が成功の鍵だと主張する。

```
        ┌─────────────┐
        │   LEARN     │ ← 何を学んだか？次の仮説は？
        │  （学習）    │
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │   BUILD     │ ← MVP（最小限の実験可能な製品）
        │  （構築）    │
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │  MEASURE    │ ← 定量的データで検証
        │  （計測）    │
        └─────────────┘
```

**核心：** 重要なのはサイクルの速度であって、各ステップの完璧さではない。**1回の完璧な試行より、10回の粗い試行のほうが学びが多い。**

ただし、Riesが見落としがちな点：**何を検証するか（仮説）の質が低いと、速いサイクルも無意味になる。** ここに「思考」の不可欠さがある。

> 📚 出典: Ries, E. (2011). *The Lean Startup*. Crown Business.

### 1.4 OODA ループ vs PDCA サイクル

| 項目 | OODA | PDCA |
|------|------|------|
| 起源 | 軍事（ジョン・ボイド大佐） | 品質管理（デミング） |
| 速度 | **高速** — 相手より速く回す | **着実** — 各段階を丁寧に |
| 適用場面 | 変化が速い、不確実性が高い | 安定した環境での継続改善 |
| 思考/試行比率 | 試行寄り（Act→再Observe） | 思考寄り（Plan→Check重視） |
| 弱点 | 浅い意思決定のリスク | 変化への対応が遅い |

**使い分けの指針：**
- **OODA**：新規事業、競合との戦い、テクノロジー選定 → 試行重視
- **PDCA**：品質改善、業務効率化、確立されたプロセス → 思考重視

> 📚 出典: Boyd, J. (1986). "Patterns of Conflict." / Deming, W.E. (1986). *Out of the Crisis*. MIT Press.

### 1.5 10,000時間の法則 vs 意図的な練習

**Gladwellの「10,000時間の法則」は誤解されている。**

Ericsson（原著者）の研究が示すのは：
- 単なる反復（ナイーブな試行）は上達に直結しない
- **意図的な練習（Deliberate Practice）** が鍵：弱点の特定 → 集中的訓練 → フィードバック → 修正
- つまり「思考を伴う試行」だけがカウントされる

**実践的含意：**

```
❌ 10,000回ただ繰り返す（試行のみ）
❌ 10,000時間理論を勉強する（思考のみ）
✅ 1回やる → 振り返る → 弱点を特定 → 集中的に改善 → 繰り返す
```

> 📚 出典: Ericsson, K.A., Krampe, R.T., & Tesch-Römer, C. (1993). "The Role of Deliberate Practice in the Acquisition of Expert Performance." *Psychological Review*, 100(3), 363-406. / Macnamara, B.N., Hambrick, D.Z., & Oswald, F.L. (2014). "Deliberate Practice and Performance in Music, Games, Sports, Education, and Professions: A Meta-Analysis." *Psychological Science*, 25(8), 1608-1618.

### 1.6 System 1 vs System 2（カーネマン）

Daniel Kahnemanの二重過程理論：

| | System 1（直感） | System 2（熟考） |
|--|-----------------|-----------------|
| 速度 | 高速・自動 | 遅い・意識的 |
| エネルギー | 低コスト | 高コスト |
| 得意分野 | パターン認識、繰り返し判断 | 論理的推論、未知の問題 |
| エラー | 認知バイアスに弱い | 情報過負荷に弱い |

**熟練者のSystem 1は、膨大なSystem 2の蓄積。** チェスのグランドマスターの「直感」は、50,000以上のパターンの無意識的認識である（Simon & Chase, 1973）。

**実践的含意：**
- 初心者は**System 2（思考）を使わざるを得ない** → だからこそ試行して経験を蓄積し、System 1を鍛える必要がある
- 熟練者は**System 1（直感）で素早く判断し、System 2で検証する** → 試行→直感的評価→修正のサイクルが速い
- **危険なのは中級者**：System 1がまだ不十分なのに、System 2を省略して直感に頼る（ダニング・クルーガー効果）

> 📚 出典: Kahneman, D. (2011). *Thinking, Fast and Slow*. Farrar, Straus and Giroux. / Simon, H.A. & Chase, W.G. (1973). "Skill in Chess." *American Scientist*, 61(4), 394-403.

### 1.7 発散的思考 vs 収束的思考

Guilford（1967）以来の創造性研究が示す重要な知見：

**創造的プロセスは発散と収束の反復**であり、一方向ではない。

```
発散（広げる）→ 収束（絞る）→ 発散 → 収束 → ...
  [試行的]      [思考的]     [試行的]  [思考的]
```

最近の神経科学研究（Beaty et al., 2015）によれば、創造性はデフォルトモードネットワーク（自由連想）と実行制御ネットワーク（評価・選択）の**動的な切り替え**に依存する。

**実践的含意：**
- 「ブレスト」と「評価」を同時にやらない
- 発散フェーズでは判断を保留し、量を出す
- 収束フェーズでは厳密に評価し、選択する
- **切り替えのタイミングを意識的に管理する**

> 📚 出典: Guilford, J.P. (1967). *The Nature of Human Intelligence*. McGraw-Hill. / Beaty, R.E., et al. (2015). "Default and Executive Network Coupling Supports Creative Idea Production." *Scientific Reports*, 5, 10964.

### 1.8 仮説→実験→検証のサイクル速度と成果

科学史の研究から：

- **エジソン**：「私は失敗したのではない。うまくいかない方法を10,000通り見つけたのだ」→ 超高速試行（ただし体系的な記録と分析を伴う）
- **ダーウィン**：20年以上の思考と観察の後に『種の起源』を出版 → 深い思考型
- **ワトソン＆クリック**：複数のモデルを物理的に組み立てて試す → 思考と試行の高速交互

**パスツールの名言：** 「幸運は準備された心にのみ訪れる」— 思考（準備）があってこそ、試行（セレンディピティ）が活きる。

## 2. 人のタイプによる違い

### 2.1 初心者 vs 熟練者

```
             思考の質
               ▲
               │      ★熟練者
               │      高品質な思考 + 効率的な試行
               │
               │   △中級者
               │   思考の質が上がるが、試行が減りがち
               │   （「分かったつもり」の罠）
               │
               │ ○初心者
               │ 思考の質が低い → 試行で補う必要がある
               └──────────────────────────► 試行の量
```

| ステージ | 最適バランス | 理由 |
|---------|------------|------|
| **初心者** | 試行80% : 思考20% | 知識がないので考えても空回り。まず手を動かして感覚を掴む |
| **中級者** | 試行50% : 思考50% | 基礎知識あり。仮説を立てて検証するサイクルが最も効率的 |
| **熟練者** | 試行30% : 思考70% | 豊富な経験（System 1）があるので、思考の質が高い。少ない試行で的を射る |
| **マスター** | 思考と試行が融合 | 「考えながら動く」「動きながら考える」が一体化。区別が無意味になる |

---

### 2.2 性格特性（Big Five）との関連

| Big Five特性 | 思考/試行の傾向 | リスク |
|-------------|---------------|--------|
| **開放性が高い** | 試行寄り（新しいことを試したがる） | 深掘りせずに次へ行きがち |
| **誠実性が高い** | 思考寄り（計画的、慎重） | Analysis Paralysis（考えすぎて動けない） |
| **神経症傾向が高い** | 思考寄り（リスク回避） | 失敗恐怖で試行を避ける |
| **外向性が高い** | 試行寄り（行動的） | 振り返りが浅くなりがち |

---

### 2.3 二つのアンチパターン

**🔴 考えすぎて動けない人（Over-Thinker）**

症状：
- 完璧な計画ができるまで始められない
- 「もう少し調べてから…」が口癖
- 失敗への恐怖が行動を止めている

処方箋：
- **5分ルール**：5分だけやってみる。5分後に続けるか判断する
- **最悪のシナリオを書き出す**：大抵は思ったほど悪くない
- **「学習」を目標にする**：成功/失敗ではなく「何を学んだか」で測る

**🔴 動きすぎて学ばない人（Over-Doer）**

症状：
- 同じ失敗を繰り返す
- 振り返りの時間を取らない
- 「忙しい」のに進んでいない

処方箋：
- **日次レトロスペクティブ**：毎日5分、「今日学んだこと」を書く
- **3回ルール**：同じ問題に3回ぶつかったら、立ち止まって根本原因を考える
- **仮説を言語化してから試す**：「これをやったら○○になるはず」と書いてから実行

### 2.4 ドメインによる違い

| ドメイン | 最適比率 | 理由 |
|---------|---------|------|
| **アート・クリエイティブ** | 試行70% : 思考30% | 予測不可能性が価値。偶然の発見が重要 |
| **エンジニアリング** | 試行40% : 思考60% | 設計ミスのコストが高い。ただしプロトタイプは有効 |
| **ビジネス・起業** | 試行60% : 思考40% | 市場は予測不能。顧客の声 > 社内の議論 |
| **科学研究** | 試行40% : 思考60% | 仮説の質が実験の効率を決める |
| **医療・航空** | 試行10% : 思考90% | 失敗コストが極めて高い。シミュレーション重視 |

## 3. AI時代の変化

### 3.1 試行コストの劇的低下

AI以前とAI以後で、試行のコスト構造が根本的に変わった：

| 活動 | AI以前 | AI以後 | コスト変化 |
|------|--------|--------|-----------|
| プロトタイプ作成 | 数日〜数週間 | 数分〜数時間 | **1/100** |
| コード実装 | 数時間〜数日 | 数分〜数十分 | **1/10〜1/50** |
| リサーチ | 数日 | 数十分 | **1/10** |
| デザイン案 | 数時間 | 数分 | **1/20** |
| 文章の推敲 | 数時間 | 数分 | **1/10** |

**含意：** 試行コストが下がると、最適バランスは試行側にシフトする。バンディット問題で言えば、各腕を引くコストがほぼゼロなら、とにかく多く引いて情報を集めるのが合理的。

---

### 3.2 バイブコーディングの功罪

Andrej Karpathyが命名した「Vibe Coding」——AIに自然言語で指示し、生成されたコードの「バイブ」（雰囲気）で判断するスタイル：

**功（メリット）：**
- プロトタイプ速度が最大70%向上（Nucamp, 2025調査）
- 非エンジニアもソフトウェアを作れる（民主化）
- アイデア検証のサイクルが劇的に速くなる

**罪（リスク）：**
- AIが生成したコードの19%にセキュリティ問題（同調査）
- 理解せずにコードを受け入れる → 技術的負債の蓄積
- 問題解決能力の深さが失われるリスク
- 「動いているから正しい」という誤認

**バイブコーディングの正しい使い方：**
```
✅ 探索フェーズ：バイブコーディングで高速プロトタイプ → 方向性を検証
✅ 学習フェーズ：AIに生成させた後、「なぜこう書いたのか」を理解する
❌ 本番コード：バイブで生成 → そのままデプロイ
❌ 思考放棄：「AIが書いたから大丈夫」
```

---

### 3.3 新しい分業モデル

AI時代の思考/試行の分業は4つのモデルがある：

```
モデル1: 人間が考え、AIが試行する
┌──────────┐    ┌──────────┐
│  人間     │───▶│   AI     │
│ 戦略・判断 │    │ 実装・実験 │
└──────────┘    └──────────┘
→ 最も一般的。人間がプロンプトで方向を決め、AIが高速実行。

モデル2: AIが考え、人間が試行する
┌──────────┐    ┌──────────┐
│   AI     │───▶│  人間     │
│ 分析・提案 │    │ 実践・検証 │
└──────────┘    └──────────┘
→ AIがデータ分析・戦略提案、人間が現場で実行・検証。

モデル3: 並列試行（AIが複数案を同時実行）
┌──────────┐    ┌─── AI案1 ───┐
│  人間     │───▶│─── AI案2 ───│───▶ 人間が選択
│ 方向決定  │    │─── AI案3 ───│
└──────────┘    └─────────────┘
→ AIの並列性を活かす。トーナメント方式で最善案を選ぶ。

モデル4: 思考と試行の融合（AIペア）
┌─────────────────────┐
│  人間 ⟷ AI          │
│  対話しながら        │
│  考え、同時に試す    │
└─────────────────────┘
→ ペアプログラミング的。最も創造性が高い。
```

---

### 3.4 並列試行の戦略

AIによって「同時に複数を試す」ことが可能になった。これは思考/試行のバランスを根本的に変える：

**従来：** 思考で選択肢を絞ってから、1つずつ試行
**AI時代：** 思考で大まかな方向を決めたら、複数を並列試行 → 結果を見て判断

```
Phase 1: 大量生成（発散）
  → AIに10-20案を並列生成させる

Phase 2: トーナメント（収束）
  → 人間が上位3-5案を選択

Phase 3: 深掘り（集中試行）
  → 選んだ案をAIと共に精緻化

Phase 4: 統合（思考）
  → 最良の要素を組み合わせて最終案
```

この戦略は、**思考の負荷を「事前の絞り込み」から「事後の評価・選択」にシフト**させる。

## 4. 実践者の声・事例

### 4.1 「Move Fast and Break Things」vs「Measure Twice, Cut Once」

| 哲学 | 代表者 | 適用場面 | 限界 |
|------|--------|---------|------|
| **Move Fast and Break Things** | Mark Zuckerberg (Facebook初期) | 新市場開拓、ソフトウェア | 規模拡大後に技術的負債と社会的問題が噴出 |
| **Measure Twice, Cut Once** | 伝統的工学・建築 | 物理的製造、インフラ | 変化が速い市場では遅すぎる |
| **Make it Work, Make it Right, Make it Fast** | Kent Beck | ソフトウェア開発 | 「Make it Right」を省略しがち |

**注目すべき進化：** Facebook自身が2014年に「Move Fast with Stable Infrastructure」にモットーを変更。試行重視から思考とのバランスへシフトした。

---

### 4.2 Y Combinator の哲学

Paul Graham / YCの核心的教え：

1. **「Launch early, iterate」** — 完璧を待つな、出して学べ
2. **「Do things that don't scale」** — 初期は手作業でOK。スケールは後から考える
3. **「Talk to users」** — 社内で考えるより顧客と話せ

ただし、YCが**暗黙に前提としていること**：
- 創業者は深いドメイン知識を持っている（思考の蓄積がある）
- 「何を作るか」の大きな方向は考え抜いている
- 試行するのは「How」であって「Why」ではない

→ **「What/Whyは深く思考、Howは高速試行」がYCの実質的な教え。**

---

### 4.3 日本の「改善」vs シリコンバレーの「Fail Fast」

| 特性 | 改善（Kaizen） | Fail Fast |
|------|---------------|-----------|
| 哲学 | 小さな改善の積み重ね | 大きな賭けで素早く学ぶ |
| リスク許容度 | 低（既存を壊さない） | 高（壊しても直せばいい） |
| イノベーション型 | 漸進的（Incremental） | 破壊的（Disruptive） |
| 文化的背景 | 恥の文化、集団主義 | 個人主義、失敗は名誉 |
| 強み | 品質、信頼性、持続性 | スピード、革新性 |
| 弱み | 破壊的イノベーションに弱い | 品質問題、燃え尽き |

**統合の視点：** 両者は対立ではなく補完。**探索フェーズではFail Fast、改善フェーズではKaizen**が最適。

> Forbes (2018) が指摘するように、「Fail Fast」の本質は「失敗を楽しむ」ことではなく「反復的であること（be iterative）」——これはKaizenとほぼ同じ精神。

## 5. 統合フレームワーク：思考-試行コンパス

### 5.1 コンパス・マトリクス

以下の2軸で状況を判断し、最適な思考/試行バランスを決定する：

```
                    不確実性が高い
                         ▲
                         │
          ┌──────────────┼──────────────┐
          │              │              │
          │   探索モード  │  賭けモード   │
          │  Trial 80%   │  Think 50%   │
          │  Think 20%   │  Trial 50%   │
          │              │              │
 失敗コスト ◄─────────────┼─────────────► 失敗コスト
   低い    │              │              │    高い
          │   習得モード  │  慎重モード   │
          │  Trial 60%   │  Think 80%   │
          │  Think 40%   │  Trial 20%   │
          │              │              │
          └──────────────┼──────────────┘
                         │
                    不確実性が低い
```

### 5.2 各モードの詳細

**🟢 探索モード（不確実性高 × 失敗コスト低）**
- 典型例：新しい技術の学習、サイドプロジェクト、ブレインストーミング
- 戦略：とにかく試す。広く浅く。記録だけ残す
- AI活用：並列で大量生成 → 面白いものを深掘り
- サイクル：**分単位**

**🟡 賭けモード（不確実性高 × 失敗コスト高）**
- 典型例：起業、大きな投資、キャリアチェンジ
- 戦略：小さく試してから大きく賭ける。撤退基準を事前に決める
- AI活用：シナリオ分析、リスク評価
- サイクル：**週〜月単位**

**🔵 習得モード（不確実性低 × 失敗コスト低）**
- 典型例：スキル向上、業務改善、既知のフレームワーク学習
- 戦略：意図的な練習。弱点に集中。量をこなす
- AI活用：即座のフィードバック、練習問題の生成
- サイクル：**時間〜日単位**

**🔴 慎重モード（不確実性低 × 失敗コスト高）**
- 典型例：本番デプロイ、医療判断、法的決定
- 戦略：徹底的なレビュー、チェックリスト、複数人検証
- AI活用：網羅的チェック、エッジケース検出
- サイクル：**日〜週単位**

---

### 5.3 AI時代の修正係数

AIが使える場合、上記のマトリクスに以下の修正を加える：

```
AI修正後の試行比率 = 基本試行比率 × (1 + AIレバレッジ係数)

AIレバレッジ係数の目安：
- コード生成・プロトタイプ: +0.5〜+1.0（試行比率を1.5〜2倍に）
- リサーチ・分析: +0.3〜+0.5
- 物理的作業: +0（AIの恩恵なし）
- クリエイティブ生成: +0.5〜+0.8
```

**ただし上限あり：** 試行比率が90%を超えると「考えなさすぎ」の領域。最低10%の思考（振り返り・統合）は確保する。

### 5.4 Yuki + エーテルのペア最適戦略

人間（Yuki）とAIエージェント（エーテル）のペアとしての最適分業：

```
┌─ Yuki（人間）の役割 ─────────────────────────┐
│                                              │
│  🎯 WHY（なぜやるか）の決定                    │
│  🧭 方向性の判断・価値観の適用                  │
│  🎨 美的・感覚的な評価                         │
│  🤝 人間関係・コミュニケーション                │
│  ⚖️ 倫理的判断                                │
│  💡 「面白い」「気持ち悪い」の直感              │
│                                              │
└──────────────────────────────────────────────┘
                    ⟷ 対話
┌─ エーテル（AI）の役割 ───────────────────────┐
│                                              │
│  🔨 HOW（どう実現するか）の高速実行            │
│  📊 網羅的な調査・分析                         │
│  🔄 並列試行・バリエーション生成               │
│  📝 記録・構造化・文書化                       │
│  🔍 見落とし・盲点の指摘                       │
│  🧮 論理的整合性のチェック                     │
│                                              │
└──────────────────────────────────────────────┘
```

**具体的なワークフロー：**

1. **Yukiが問いを投げる**（思考：What/Why）
2. **エーテルが複数案を生成**（並列試行）
3. **Yukiが直感で選択・方向修正**（思考：評価）
4. **エーテルが深掘り・実装**（集中試行）
5. **Yukiが最終判断**（思考：統合）
6. **エーテルが記録・振り返りを支援**（メタ思考）

## 6. 明日から使える具体的指針

### 6.1 日常のチェックリスト

毎朝、今日のタスクに対して自問する：

```
□ このタスクの不確実性は高い？低い？
□ 失敗したときのコストは大きい？小さい？
  → コンパス・マトリクスで今日のモードを決める

□ 自分は今「考えすぎ」？「動きすぎ」？
  → 逆方向に5%シフトする

□ AIに並列試行させられる部分はある？
  → あるなら、まず3-5案を生成させてから判断する

□ 今日の学びを記録する時間を確保したか？
  → 最低5分の振り返り時間を確保
```

### 6.2 思考/試行の切り替えタイマー

**ポモドーロの変形版：**

```
【探索モード】
  試行 25分 → 振り返り 5分 → 試行 25分 → ...
  （試行:思考 = 5:1）

【バランスモード】
  思考 15分 → 試行 25分 → 振り返り 10分 → ...
  （思考:試行 = 1:1）

【慎重モード】
  思考 25分 → 試行 15分 → 検証 10分 → ...
  （思考:試行 = 7:3）
```

### 6.3 「考えるべきか、動くべきか」の即決フローチャート

```
今の状況は？
  │
  ├─ 全く新しいことに挑戦している
  │   └─ → 動け。10分だけ試してみろ。
  │
  ├─ 前に似たことをやったことがある
  │   └─ 前回うまくいった？
  │       ├─ Yes → 同じ方法で動け。改善点だけ考えろ。
  │       └─ No → 15分考えろ。何が違うか分析してから動け。
  │
  ├─ 失敗すると取り返しがつかない
  │   └─ → 考えろ。チェックリストを作れ。人に相談しろ。
  │
  ├─ 30分以上考えているのに進んでいない
  │   └─ → 考えるのをやめろ。最小限の試行をしろ。
  │
  └─ AIに任せられる作業である
      └─ → 3案並列生成させろ。その間に別のことを考えろ。
```

### 6.4 週次レビューテンプレート

```markdown
## 今週の思考/試行レビュー

### 試行したこと
- [ ] 何を試した？
- [ ] 何を学んだ？
- [ ] 次に活かせることは？

### 考えたこと
- [ ] どんな仮説を立てた？
- [ ] 検証できた？できなかった？
- [ ] 考えすぎて動けなかったことは？

### バランスの自己評価
- 今週は考えすぎ？動きすぎ？ちょうどいい？
- 来週はどちらにシフトすべき？

### AIの活用度
- AIに任せてうまくいったこと
- AIに任せて失敗したこと（人間の判断が必要だった）
- もっとAIを活用できた場面
```

## まとめ：3つの黄金律

### 1. 🎯 「試行コストが低いなら、考えるより試せ」
AIによって試行コストが劇的に下がった今、「まず3案作ってから考える」が新しいデフォルト。

### 2. 🔄 「試行の質は、振り返りの質で決まる」
100回の無反省な試行より、10回の意図的な練習のほうが価値がある。試行→振り返り→仮説更新のサイクルを回せ。

### 3. 🧭 「不確実性と失敗コストでモードを切り替えろ」
万能の比率は存在しない。状況に応じて思考/試行のバランスを動的に調整する。コンパス・マトリクスを使え。

---

> *「最善の思考は試行から生まれ、最善の試行は思考から生まれる。両者は円環であって、直線ではない。」*
